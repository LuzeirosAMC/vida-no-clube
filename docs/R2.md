# Ativação do Cloudflare R2

O R2 é necessário somente para fotos enviadas por usuários. Não é necessário para as imagens que já estão em `public/media/`.

## Antes de ativar

- Obtenha autorização do responsável pela conta e confirme a forma de cobrança;
- Defina quem poderá moderar imagens;
- Defina uma política de retenção e remoção;
- Nunca torne o bucket público: a aplicação deve controlar o acesso.

## Configuração

1. Na conta Cloudflare do clube, crie um bucket, por exemplo `luzeiros-vida-no-clube-media`;
2. Em `wrangler.production.jsonc`, adicione no nível principal:

```jsonc
"r2_buckets": [
  {
    "binding": "BUCKET",
    "bucket_name": "luzeiros-vida-no-clube-media"
  }
]
```

3. Execute `npm run build`;
4. Publique com `npm run deploy:cloudflare`;
5. Confirme no painel do Worker que `BUCKET` aparece nos bindings;
6. Reative na interface o campo de foto do formulário de envio;
7. Teste JPG, PNG e WebP válidos e um arquivo inválido;
8. Confirme que uma foto pendente não abre publicamente;
9. Aprove a foto e confirme a exibição por `/api/media/:id`;
10. Rejeite uma foto de teste e verifique a política de remoção.

## Fluxo de segurança já implementado

- Somente usuário autenticado envia conteúdo;
- Limite de 8 MB;
- Tipos aceitos: `image/jpeg`, `image/png` e `image/webp`;
- Nome do objeto é aleatório e não deriva do nome original;
- O bucket não precisa de domínio público;
- A rota de mídia consulta o D1 e exige status `approved`;
- A resposta usa `X-Content-Type-Options: nosniff`.

## Trabalho restante ao ativar

O backend já está preparado, mas a interface atual envia apenas `kind=comment`. Ao ativar o R2, o formulário em `app/minha-conta/submission-form.tsx` precisa voltar a oferecer:

- seletor entre relato e foto;
- campo `<input type="file">` com `accept="image/jpeg,image/png,image/webp"`;
- texto informando limite e moderação;
- pré-visualização opcional no navegador.

Também é recomendável excluir do bucket os objetos rejeitados e criar uma rotina para detectar arquivos órfãos.

## Desativação emergencial

Para suspender novos uploads sem afetar o restante do site, remova o binding `BUCKET` do Worker e publique novamente. O código voltará a responder que fotos estão temporariamente indisponíveis. Objetos já armazenados não são apagados automaticamente.
